# 特性规格：界面打磨与体验优化

**特性分支**：`004-ui-design`

**创建日期**：2026-10-05

**状态**：进行中（设计方案全部确认，待实施）

**输入**：用户描述："在 003 功能框架之上，做 UI 设计与优化——建立设计系统、打磨阅读器体验、升级任务列表/详情页视觉、响应式适配、暗色模式、微交互动效、登录/Landing 页美化。"

**已确认的设计决策**：

- **配色体系**：双配色体系
  - 阅读页：墨林墨绿（米灰底 `#faf8f3` + 暖灰字 `#3d3a33` + 墨绿 `#3d7a52` 点缀），护眼舒适
  - 非阅读页：柔墨（纯灰调，主色 `#27272a`，低对比度，极简高级感）
  - 两套配色独立管理，进入阅读器有"翻开书"的仪式感但不割裂

- **阅读器风格**：简约精致风（方案 B 去渐变）——排版取胜，无渐变装饰，小圆点导航激活态，顶部阅读进度条

- **任务列表/详情页**：
  - 卡片：舒适版（~120px，标题+两行元信息+进度条+底部按钮）
  - 空态：简约几何（SVG 文档图标 + 引导文案 + CTA 按钮）
  - 步骤条：数字圆圈式（已完成 ✓ + 当前脉冲光环 + 未开始空心数字）
  - 结果卡片：信息优先（4 个统计数字 + 底部按钮）
  - 失败分类：弱区分（统一卡片风格，仅图标颜色不同）

- **Landing/登录/导航**：
  - Landing 风格：图文对比风（左文右图 + 6 功能卡片 + CTA + Footer，无使用场景/定价板块）
  - 登录页：居中卡片式布局
  - 用户菜单：完整款（6 项：我的任务/个人设置/密钥管理/帮助文档/反馈建议/退出登录）
  - 提交页：卡片分区式（PDF/链接选项卡 + 拖拽上传，无高级设置）
  - Logo：林中一叶（叶片 + 圆形，自然学术感）
  - Landing 动效：毛玻璃导航、背景光晕漂浮、首屏渐入、卡片悬浮、按钮扫光等

- **响应式**：
  - 手机端：能用就行（最低可用性保障，不追求像素级精致）
  - 移动端导航：左侧滑出抽屉式

- **微交互**：
  - 路由切换：淡入淡出过渡
  - 骨架屏范围：任务列表、任务详情需要；阅读器、设置页不需要
  - 三态规范：加载态/空态/错误态视觉规范统一设计

## 用户场景与测试 *（必填）*

### 用户故事 1 - 设计系统与全局视觉规范（优先级：P1）

作为产品的使用者，我打开任意页面都能感受到统一的设计语言——配色协调、字体有层级、间距有节奏、圆角和阴影有规范，
而不是各个页面各用各的样式、像拼凑起来的。我可以一键切换浅色/暗色主题，切换后所有页面都自然适配，没有半黑半白的割裂感。

**为什么是这个优先级**：设计系统是所有 UI 优化的地基——没有统一的 token（配色/字体/间距/圆角），
后面每个页面的美化都是零散的、不可维护的。暗色模式也必须建立在 token 体系之上才能干净利落地实现。

**独立测试**：打开所有页面逐一检查，配色、字体、间距、按钮样式、卡片样式全局一致；切换暗色模式后所有页面无错位、无硬编码白色背景、无不可读文字。

**验收场景**：

1. **假定**用户打开应用的任一页面（任务列表、任务详情、阅读器、提交任务、密钥设置、登录、注册），
   **当**浏览页面时，**那么**所有页面使用统一的配色方案、字体层级、间距规范、圆角和阴影风格，
   不存在页面间风格割裂的情况。
2. **假定**设计系统定义了 CSS 变量（design tokens），**当**开发者需要调整全局样式时，
   **那么**只需修改 token 变量即可全局生效，不需要逐个页面查找硬编码值。
3. **假定**用户点击主题切换按钮（浅色/暗色），**当**切换到暗色模式时，**那么**所有页面的背景、文字、
   边框、卡片、输入框等全部自然适配暗色主题，文字清晰可读、对比度足够，不存在白底黑字或黑底白字的硬编码残留。
4. **假定**用户刷新页面或重新登录，**当**回到应用时，**那么**主题选择被记住（存在 localStorage），
   不需要每次重新切换。
5. **假定**用户的系统设置为暗色模式且从未手动切换过主题，**当**首次打开应用时，
   **那么**应用自动跟随系统偏好（可选，最低要求是有手动切换且记忆）。

### 用户故事 2 - 阅读器体验打磨（优先级：P1）

作为阅读转写成品的用户，我希望阅读体验舒适、可控：可以切换阅读主题（浅色/护眼/暗色）、调节字号和行高、
章节导航精致好用、图片可以点击放大查看、公式可以放大、有阅读进度感知。整体风格简约精致，
以米灰底色+暖灰文字为主，墨绿点缀，用排版和细节取胜，没有花哨的渐变和装饰。

**为什么是这个优先级**：阅读器是产品核心价值的兑现页面——用户花最多时间的地方、最能体现产品质感的地方。
003 只搭了功能框架，体验打磨直接决定用户对产品的第一印象和留存意愿。

**独立测试**：进入阅读器，验证三主题切换、字号 A-/A+、行高调节、章节导航高亮同步、图片点击灯箱、
阅读进度条、折叠区展开/收起动画、返回顶部按钮；全部交互流畅无 bug。

**验收场景**：

1. **假定**用户进入阅读器页面，**当**浏览页面时，**那么**整体风格为简约精致风：米灰底色+暖灰文字为主色调、墨绿点缀、无渐变装饰、
   排版考究、细节（导航激活态、章节标题、公式块、折叠区）精致，无任何渐变装饰。
2. **假定**用户想要切换阅读主题，**当**点击主题切换按钮时，**那么**可以在「浅色」「护眼（羊皮纸/米黄）」
   「暗色」三种主题之间切换，切换后正文区、导航区、顶部栏全部自然适配，无违和感。
3. **假定**用户觉得字号太小或太大，**当**点击 A- / A+ 按钮时，**那么**正文字号在合理范围内
   （如 12px–20px）步进调节，调节后公式、图片、折叠区等元素排版不崩坏。
4. **假定**用户想要调节行高，**当**选择 1.6 / 1.8 / 2.0 三档行高时，**那么**正文行间距实时变化，
   阅读节奏更舒适。
5. **假定**用户向下滚动阅读长文，**当**浏览时，**那么**顶部（或侧边）有一条细微的阅读进度条，
   实时显示当前阅读位置占全文的比例；同时可以看到章节、字数、预计阅读时长等信息。
6. **假定**用户点击正文中的图片，**当**触发图片查看时，**那么**弹出灯箱（遮罩层 + 居中大图），
   可以点击遮罩或关闭按钮退出灯箱；图片在灯箱中可以看清细节。
7. **假定**用户想要快速回到顶部，**当**滚动超过一屏后，**那么**右下角出现返回顶部按钮，点击后平滑滚动到页面开头。
8. **假定**用户阅读时滚动经过不同章节，**当**章节切换时，**那么**左侧导航栏的当前章节自动高亮同步，
   点击导航项可平滑滚动到对应章节；深链（URL hash）直达指定章节仍然有效。
9. **假定**用户展开/收起折叠区，**当**操作时，**那么**有平滑的高度过渡动画，而不是原生 details 的生硬跳变。
10. **假定**用户使用小屏幕（平板/手机）阅读，**当**屏幕宽度不足时，**那么**左侧导航可以收起为抽屉式菜单，
    点击目录按钮滑出，正文区占满可用宽度。

### 用户故事 3 - 任务列表与详情页视觉升级（优先级：P2）

作为管理任务的用户，我希望任务列表和详情页看起来精致、信息层级清晰：任务卡片有设计感、状态标签直观、
进度条有动效、空态不只是一行文字而是有插画或引导。任务详情页的六阶段步骤条不再是朴素的默认样式，
而是有精致的状态视觉和过渡动效。

**为什么是这个优先级**：列表和详情是用户提交任务后的「等待页面」，视觉上的精致度影响用户对产品专业度的判断。
但它们不是核心价值页（阅读才是），故列 P2。

**独立测试**：打开任务列表页，检查卡片视觉、状态标签、hover 效果、空态展示；打开任务详情页，
检查步骤条视觉、进度条动效、成功/失败状态展示；全部观感统一、精致。

**验收场景**：

1. **假定**用户打开任务列表页，**当**有任务时，**那么**每个任务以卡片形式展示，卡片有 hover 动效
   （轻微上浮或阴影加深），状态标签有明确的色彩区分但不刺眼，进度条精致有过渡。
2. **假定**用户还没有任何任务，**当**打开任务列表时，**那么**页面显示空态设计——有简洁的插画或图标、
   友好的引导文案、清晰的「新建任务」按钮，而不是光秃秃的一行文字。
3. **假定**用户打开一个正在运行的任务详情页，**当**任务推进时，**那么**六阶段步骤条有精致的视觉样式：
   已完成阶段有对勾或高亮、当前阶段有脉冲或呼吸效果、未开始阶段为灰色，阶段切换有平滑过渡。
4. **假定**任务成功完成，**当**进入终态时，**那么**成功状态以卡片化形式展示结果信息（标题、章节数、字数、耗时），
   阅读和下载按钮突出且有设计感。
5. **假定**任务失败，**当**进入终态时，**那么**失败状态有清晰的三分类视觉标识（输入类/系统类/超限类），
   错误说明排版清晰，重试/返回按钮醒目。
6. **假定**任务正在排队或运行中，**当**等待时，**那么**页面有骨架屏或加载动效，而不是空白或光秃秃的「加载中」文字。

### 用户故事 4 - 登录/Landing 页与全局导航美化（优先级：P2）

作为第一次访问产品的用户，我希望登录页和落地页看起来专业、有品牌感，而不是朴素的表单堆砌。
顶部导航栏精致好用，用户菜单有设计感，整体第一印象就像一个认真做的产品。

**为什么是这个优先级**：登录/Landing 是用户的第一印象，但用户停留时间短、交互少；导航栏是全局元素，
改一次全站生效。重要但不如阅读器和任务页紧迫。

**独立测试**：打开登录页、注册页、Landing 页，检查视觉设计和品牌感；检查顶部导航栏的样式、hover 效果、
用户菜单；全部精致统一。

**验收场景**：

1. **假定**用户未登录时访问应用，**当**看到 Landing 页时，**那么**页面有品牌感——产品名称、一句话定位、
   核心功能简介（2–3 个卖点）、登录/注册入口，排版精致、视觉舒适。
2. **假定**用户进入登录/注册页，**当**填写表单时，**那么**表单居中卡片式布局，输入框有 focus 状态、
   按钮有 hover 效果，整体风格与应用内一致，不像是另一个产品。
3. **假定**用户登录后看到顶部导航栏，**当**浏览时，**那么**导航栏精致：品牌 Logo 区域清晰、导航项
   有 hover/active 状态指示、用户头像/名称有下拉菜单、整体与页面内容有层次区分。
4. **假定**用户点击右上角用户名，**当**展开用户菜单时，**那么**菜单有设计感（卡片式、阴影、圆角），
   菜单项有 hover 效果，包含「设置」「退出登录」等选项。

### 用户故事 5 - 响应式适配与微交互（优先级：P3）

作为在不同设备上使用产品的用户，我希望在平板和手机上也能正常使用，布局会自动适配屏幕宽度。
同时，页面之间的切换、按钮的点击、卡片的悬停都有细腻的微交互，让产品感觉「活」起来。

**为什么是这个优先级**：响应式和微交互是锦上添花——产品的核心使用场景是桌面端（学术阅读），
但做好了能显著提升品质感。工作量不小但不阻塞核心功能，故列 P3。

**独立测试**：用浏览器开发者工具分别模拟平板（768px）和手机（375px）宽度，检查所有页面布局是否合理、
有无横向滚动条、关键操作是否可达；检查页面切换过渡、按钮 hover/active 效果、骨架屏加载等微交互。

**验收场景**：

1. **假定**用户在平板宽度（≈768px）下使用，**当**浏览各页面时，**那么**布局自动适配：导航栏可折叠、
   内容区占满宽度、卡片自适应排列，没有横向滚动条，所有功能按钮可达。
2. **假定**用户在手机宽度（≈375px）下使用，**当**浏览各页面时，**那么**布局转为单列：顶部导航变为汉堡菜单、
   任务列表卡片垂直堆叠、阅读器导航收起为抽屉、表单全宽显示，核心操作（提交、阅读、下载）拇指可及。
3. **假定**用户在页面之间跳转，**当**路由切换时，**那么**有轻微的淡入淡出或滑动过渡效果，
   而不是生硬的白屏闪烁。
4. **假定**用户将鼠标悬停在按钮、卡片、导航项等可交互元素上，**当** hover 时，**那么**有明确的视觉反馈
   （颜色变化、阴影变化、轻微缩放等），反馈时间在 150ms 以内，感觉跟手。
5. **假定**页面正在加载数据，**当**等待时，**那么**显示骨架屏（与实际内容布局一致的灰色占位），
   而不是转圈 loading 或空白，内容加载完成后有平滑的出现过渡。

### 边界情况

- 用户在暗色模式下刷新页面：主题选择持久化，刷新后仍为暗色，不出现白色闪烁（FOUC）。
- 阅读器主题（浅色/护眼/暗色）与全局主题的关系：阅读器主题独立于全局主题，各自记忆；
  但默认情况下，阅读器暗色主题与全局暗色模式联动（全局切暗色时阅读器也切暗色，用户可单独覆盖）。
- 超大字号下的排版：字号调到最大时，公式、图片、折叠区等元素不溢出、不重叠，仍可正常阅读。
- 极端宽屏下的阅读体验：正文最大宽度限制在合理范围（如 720px），两侧留白，不出现一行 200 字的情况。
- 图片灯箱在超长图/超宽图下的适配：图片按比例缩放，不超出视口，可滚动查看（或仅按比例缩小）。
- 折叠区内包含公式或图片：展开动画顺畅，公式排版在展开后正确重绘（KaTeX 可能需要触发重排）。
- 无障碍：颜色对比度满足 WCAG AA 标准（正文 ≥4.5:1），键盘导航可达所有交互元素。
- 减少动效偏好：系统设置了 `prefers-reduced-motion` 的用户，所有动画自动降级或关闭，不影响功能使用。

## 需求 *（必填）*

### 功能需求

**设计系统（全局 token）**

- **FR-001**：系统必须建立统一的设计 token 体系，以 CSS 变量形式定义，范围涵盖：
  配色（主色/中性色/语义色/背景色）、字体层级（标题/正文/辅助文字/代码的字号、行高、字重）、
  间距规范（4/8/12/16/20/24/32px 等刻度）、圆角（小/中/大/圆形）、阴影（小/中/大）、
  过渡动画时长与缓动函数；token 命名使用语义化命名（如 `--color-bg-primary`、`--font-size-body`），
  而非字面色值命名。
- **FR-002**：token 必须同时支持浅色和暗色两套主题，通过在 `:root` 或 `body` 上切换
  `data-theme="light" | "dark"` 属性来实现；所有页面组件必须消费 token，不得硬编码颜色值
  （除了极少数品牌色 Logo 等特例）。
- **FR-003**：主题选择必须持久化到 `localStorage`，刷新页面后保持用户选择；
  首次访问默认跟随系统 `prefers-color-scheme`（如浏览器支持），否则默认浅色。
- **FR-004**：顶部导航栏必须提供主题切换入口（浅色/暗色切换按钮或图标），一键切换全站主题。

**阅读器体验**

- **FR-005**：阅读器必须支持三种阅读主题切换：浅色（白底黑字）、护眼（米黄/羊皮纸底深棕字）、
  暗色（深灰底浅灰字）；主题切换在阅读器工具栏操作，独立于全局主题但默认跟随全局。
- **FR-006**：阅读器必须支持字号调节：提供 A- / A+ 按钮，步进 1–2px，范围约 12px–20px
  （或相对单位的等比范围），调节后正文、标题、公式、折叠区等所有文字元素同步缩放，排版不崩坏。
- **FR-007**：阅读器必须支持行高三档切换（1.6 / 1.8 / 2.0），用户可按需选择阅读节奏。
- **FR-008**：阅读器顶部（或内容区上方）必须显示阅读信息：论文标题、章节数、总字数、
  预计阅读时长（按 300–400 字/分钟估算）；顶部有一条细微的阅读进度条，随滚动实时更新。
- **FR-009**：左侧章节导航必须有精致的激活态：当前阅读章节用小圆点（或其他视觉标记）+ 加粗 + 高亮背景标识，
  滚动时自动同步高亮；点击导航项平滑滚动到对应章节。
- **FR-010**：正文中的图片必须支持点击放大：点击后弹出灯箱（半透明遮罩 + 居中大图 + 关闭按钮），
  点击遮罩或关闭按钮退出，按 ESC 键也可退出。
- **FR-011**：阅读器右下角必须提供返回顶部按钮：滚动超过一屏后淡入出现，点击后平滑滚动到页面顶部，
  回到顶部后淡出消失。
- **FR-012**：折叠区（details）必须有平滑的展开/收起高度过渡动画，替代原生的生硬跳变；
  折叠区标题有信息图标（i 或 ▸▾）指示状态。
- **FR-013**：阅读器整体视觉风格必须遵循「简约精致」方向：米灰底色+暖灰文字为主色调、墨绿(#3d7a52)点缀、无渐变装饰、
  用排版和细节（间距、留白、细线、小圆点）取胜；正文最大宽度限制在约 720px 以保证阅读舒适度。

**任务列表与详情页**

- **FR-014**：任务列表页必须以卡片形式展示任务：每个任务一张卡片，包含任务标题、状态标签、
  进度条（运行中任务）、创建时间、操作按钮（阅读/下载/查看详情）；卡片有 hover 效果
  （阴影加深或轻微上移），点击卡片进入详情页。
- **FR-015**：任务列表空态必须有视觉设计：包含简洁的图标/插画、友好的空态文案、醒目的「新建任务」按钮，
  引导用户创建第一个任务。
- **FR-016**：任务详情页的六阶段步骤条必须重新设计：已完成阶段有对勾标识、当前阶段有高亮/脉冲效果、
  未开始阶段为灰色；阶段切换时有平滑的视觉过渡。
- **FR-017**：任务成功状态必须以结果卡片形式展示：卡片内包含论文标题、章节数、总字数、执行耗时等信息，
  「阅读」和「下载」按钮突出显示。
- **FR-018**：任务失败状态必须有清晰的三分类视觉：输入类/系统类/超限类各有不同的图标和色彩标识，
  错误说明排版清晰，「重新提交」或「返回列表」按钮醒目。
- **FR-019**：数据加载中必须显示骨架屏：任务列表、任务详情等页面在数据加载时显示与实际布局一致的骨架屏，
  内容加载后平滑过渡。

**登录/Landing 与导航**

- **FR-020**：Landing 页必须有品牌感设计：包含产品名称、一句话定位描述、2–3 个核心功能卖点（图标+标题+简介）、
  登录/注册入口按钮；整体风格与应用内统一。
- **FR-021**：登录/注册页必须采用居中卡片式布局：表单卡片有阴影和圆角，输入框有 focus 状态样式，
  提交按钮有 hover/loading 状态；页面背景简洁不花哨。
- **FR-022**：顶部导航栏必须重新设计：品牌区清晰、导航项有下划线或背景指示 active 状态、
  右侧用户区域有头像/名称 + 下拉菜单（含设置、退出登录）；导航栏有微妙阴影或边框与内容区分层。

**响应式与微交互**

- **FR-023**：应用必须支持响应式布局：至少适配桌面（≥1024px）、平板（768–1023px）、
  手机（<768px）三个断点；平板下列表/导航自适应缩放，手机下转为单列布局+汉堡菜单。
- **FR-024**：所有可交互元素（按钮、链接、卡片、导航项）必须有 hover 和 active 状态的视觉反馈，
  过渡时间 100–200ms，使用统一的缓动函数。
- **FR-025**：页面路由切换必须有淡入淡出过渡效果，避免白屏闪烁；页面内元素的出现
  （如列表加载完成）可以有 stagger 渐入效果。
- **FR-026**：所有动画和过渡必须尊重 `prefers-reduced-motion` 系统设置：用户开启减少动效时，
  所有非必要动画自动关闭或降级为即时切换，不影响功能使用。

**横切约束**

- **FR-027**：本特性为纯前端 UI 优化，**不得修改任何后端代码**（包括 API、数据模型、业务逻辑），
  也不得修改 core/ 目录的任何内容；所有变更仅限于 webui/ 前端项目内。
- **FR-028**：本特性不得引入新的运行时依赖（如 UI 组件库替换、状态管理库替换等）；
  纯 CSS/SCSS 改造优先，必要的小工具库（如 focus-trap 等）需单独评估且体积小于 5KB gzipped。
- **FR-029**：所有既有功能必须保持可用——提交任务、实时进度、阅读器、下载、密钥设置、登录注册等，
  UI 改版后功能零回归。
- **FR-030**：阅读器的安全特性（XSS 消毒、图片受控资源、归属校验）不得因 UI 改版而削弱或绕过，
  markdown.js 渲染管线保持不变。
- **FR-031**：假模式下的所有交互和视觉必须同样生效——演示任务徽章、假模式提示等元素在新 UI 中仍正确显示。
- **FR-032**：构建产物体积增幅不得超过 15%（以 gzipped JS+CSS 计），不得因 UI 美化显著影响首屏加载性能。

### 关键实体 *（涉及数据时必填）*

本特性为纯前端 UI 优化，**不新增任何后端数据模型或持久化实体**。

前端新增的纯客户端状态：

- **主题偏好**：存储在 `localStorage`，键名 `app-theme`，值 `light | dark`；默认跟随系统。
- **阅读器偏好**：存储在 `localStorage`，键名 `reader-prefs`，值为 JSON 对象
  `{ theme: "light"|"eye-care"|"dark", fontSize: number, lineHeight: number }`。
- **导航折叠状态**：响应式下侧边导航的展开/收起状态，存储在 `localStorage`（可选）。

## 假设

- 设计系统采用 CSS 变量 + data-theme 属性切换方案，不引入 CSS-in-JS 或额外的主题管理库。
- 阅读器的 Markdown 渲染管线（markdown.js + DOMPurify + KaTeX）保持不变，UI 优化只在外层容器、
  排版样式和交互控件上做文章，不修改渲染逻辑。
- 暗色模式只做两套（全局 light/dark），阅读器额外有护眼主题但仅限阅读器内，不影响全站。
- 响应式以桌面端为主要设计目标，平板和手机做到可用即可，不追求像素级完美的移动端体验。
- 图片灯箱使用原生实现（遮罩 div + img），不引入额外的图片查看器库。
- 骨架屏使用 CSS 动画（渐变背景移动），不引入骨架屏组件库。
- Landing 页的「插画」使用 SVG 手绘或简单几何图形，不使用 AI 生成图片或外部图片资源。
- 字体仍使用系统字体栈（不引入外部 Web Font，避免性能和字体版权问题），通过精细的字号/行高/字重搭配提升排版质感。
- 本特性完全在前端完成，后端零改动；如过程中发现必须后端配合才能实现的 UI 需求，
  需单独提出来重新评估，不在本特性范围内直接实现。
