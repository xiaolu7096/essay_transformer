# 特性规格：论文转写任务流水线

**特性分支**：`002-task-pipeline`

**创建日期**：2026-09-25

**状态**：草稿

**输入**：用户描述："在 Spec 001 的网页客户端与认证体系之上，让登录用户能管理自己的外部服务密钥、提交论文转写任务（arXiv 链接或 PDF 上传），任务在后台执行而不阻塞浏览器；用户能看到只属于自己的任务历史、当前阶段与友好失败原因，并能在阶段边界取消任务。全程支持无密钥、零外部调用的假模式离线演示。实时进度推送（SSE）与在线阅读器、成品下载不在本特性范围，归 Spec 003。"

## 用户场景与测试 *（必填）*

### 用户故事 1 - 管理我自己的外部服务密钥（优先级：P1）

作为已登录用户，转写需要两个外部服务（论文解析服务、大模型转写服务）的
密钥。我在网页上一次性录入并保存自己的密钥，之后提交任务无需重复填写；
我还能随时更新或删除它们。我确信密钥被安全保管：任何页面和接口都不会
回显完整密钥，其他任何人（包括其他用户）都接触不到我的密钥。

**为什么是这个优先级**：没有密钥管理，真实任务就无法发起；它同时是
多租户数据隔离原则在"凭据"这一最敏感资产上的第一个落点。

**独立测试**：登录后录入两个密钥，刷新页面看到的只是掩码；再次进入
设置页可以更新或删除；全程抓不到完整密钥的回显。

**验收场景**：

1. **假定**用户已登录且从未保存过密钥，**当**用户在设置页分别填入两个
   服务的密钥并保存，**那么**系统提示保存成功，并以掩码形式展示
   （仅露出可辨认的少量首尾字符）。
2. **假定**用户已保存密钥，**当**用户刷新页面或重新登录后进入设置页，
   **那么**看到的仍是掩码而不是明文，且能知道两个密钥各自是否已配置。
3. **假定**用户已保存密钥，**当**用户用新值覆盖保存，**那么**后续任务
   使用新密钥；当用户删除某个密钥，**那么**该密钥立即不再可用、
   掩码消失。
4. **假定**用户提交的密钥内容为空或只有空白，**当**尝试保存，**那么**
   系统拒绝并提示具体问题，不产生空凭据记录。
5. **假定**两个不同用户分别保存了各自的密钥，**当**任何一方查看、
   更新、删除密钥，**那么**只能操作自己的记录，系统不暴露另一方密钥
   是否存在。

### 用户故事 2 - 提交一篇论文并让它在后台转写（优先级：P1）

作为已登录用户，我用两种方式之一提交论文：粘贴一个 arXiv 论文链接，
或选择本机的一个 PDF 文件上传。提交后系统立刻给我一个任务并让我继续
操作——浏览器不会被几分钟的转写过程卡住。任务在后台依次经历摄取、
解析、归一化、规划、分章转写、拼装六个阶段，最终成功或失败。

**为什么是这个优先级**：提交与后台执行是整条流水线的核心价值，其余
故事（看状态、取消、离线演示）都依附于"任务真正跑起来"。

**独立测试**：在假模式（见用户故事 5）下，从提交页发起一个任务，
页面立即返回任务并可做其他操作；稍后该任务在不刷新整页数据的情况下
（手动刷新列表即可）呈现从排队到完成的状态推进。

**验收场景**：

1. **假定**用户已配置所需密钥（或处于假模式），**当**用户粘贴合法
   arXiv 链接并提交，**那么**系统立即创建一个任务并返回其标识与初始
   状态，提交动作不等待转写完成。
2. **假定**用户已配置所需密钥（或处于假模式），**当**用户选择一个
   合法、大小在限制内的 PDF 并提交，**那么**任务同样立即创建，文件
   被保存到该用户该任务专属的私有位置。
3. **假定**用户没有配置所需密钥且系统不在假模式，**当**用户尝试提交，
   **那么**提交被拒绝，系统明确告知缺少哪个服务的密钥并引导前往设置。
4. **假定**用户已经有一个正在运行（排队或运行中）的任务，**当**同一
   用户再次提交，**那么**系统拒绝并明确提示"先等待或取消当前任务"；
   不同用户之间互不影响。
5. **假定**任务已创建，**当**后台执行推进，**那么**任务记录持续保存
   当前阶段名、阶段内进度比例与文字状态，用户稍后打开列表就能看到
   最新快照（本特性不要求实时推送）。
6. **假定**任务转写成功，**那么**任务状态为"已完成"，并记录结果摘要
   （论文标题、章节数、总字数等），成品文件保存在该用户专属目录；
   在线阅读与成品下载不在本特性交付。

### 用户故事 3 - 查看只属于我的任务历史与可懂的失败原因（优先级：P1）

作为已登录用户，我打开任务列表回顾我发起过的所有转写：正在跑的看到
阶段进度，跑完的看到结果摘要，失败的看到**我能据此行动**的原因。
失败原因必须区分三类：是我输入的问题（换个链接/文件就能重试）、是
外部服务暂时故障（稍后重试）、还是系统自身出错（联系维护者）。我永远
看不到别人的任务，也无法通过猜测任务编号访问他人数据。

**为什么是这个优先级**：没有可追溯的历史和可行动的失败反馈，后台
长任务对用户就是黑盒；归属隔离则是多租户红线。

**独立测试**：构造成功、输入类失败、服务类失败三种任务，在列表与
详情中核对状态、进度快照、结果摘要与三类可区分的提示；再用用户 B
尝试访问用户 A 的任务标识，确认被拒绝。

**验收场景**：

1. **假定**用户发起过若干任务，**当**打开任务列表，**那么**按时间倒序
   看到自己的全部任务及其当前状态（排队/运行中/已完成/已失败/已取消），
   且不包含任何其他用户的任务。
2. **假定**任务正在运行，**当**查看该任务，**那么**能看到当前所处阶段
   （六阶段之一）、进度比例与状态文字。
3. **假定**任务因论文链接不支持、PDF 损坏或文件缺失等用户侧原因失败，
   **当**查看失败任务，**那么**系统明确归类为"输入问题"并给出可操作
   的修正建议，用户修正后可以重新提交。
4. **假定**任务因外部解析/模型服务不可用、超时、密钥被服务端拒绝等
   外部原因失败，**当**查看失败任务，**那么**系统归类为"服务问题"，
   提示稍后重试或检查密钥，不把它误报成用户输入错误。
5. **假定**任务因不属于上述两类的内部异常失败，**当**查看失败任务，
   **那么**系统归类为"系统问题"并给出统一的维护者引导，且不向前端
   暴露堆栈等内部细节。
6. **假定**用户 B 拿到或猜到用户 A 的任务标识，**当**用户 B 直接请求
   该任务，**那么**系统拒绝访问，且不承认该任务存在。
7. **假定**服务曾经重启，**当**用户查看重启前正在运行的任务，**那么**
   该任务被明确标记为"因服务中断而终止"（属于系统类、可重新提交），
   而不是永远停在运行中或被误标为成功。

### 用户故事 4 - 在阶段边界取消运行中的任务（优先级：P2）

作为已登录用户，我意识到提交错了论文或不想继续等待时，可以取消正在
运行的任务。取消在**阶段边界**安全生效：系统不会在一次外部解析轮询
途中或一个章节的生成过程中硬中断造成脏数据，而是在当前阶段收尾后、
下一阶段开始前停止，并把任务标记为"已取消"。

**为什么是这个优先级**：长任务不可取消会持续消耗用户的外部服务额度；
但它依赖执行内核先存在，因此列 P2。

**独立测试**：假模式下发起任务后立即取消，观察任务进入已取消终态，
且不会产生"已完成"成品；再尝试取消一个已完成任务，应被拒绝。

**验收场景**：

1. **假定**用户有一个排队或运行中的任务，**当**用户请求取消，**那么**
   请求立即被接受，任务不再进入任何尚未开始的新阶段，并最终呈现
   "已取消"状态。
2. **假定**取消请求与任务自然完成几乎同时发生，**当**系统处理这对
   竞争，**那么**以先到达终态者为准：要么明确已完成、要么明确已取消，
   不出现自相矛盾的状态。
3. **假定**任务已经处于终态（完成/失败/取消），**当**用户再次请求
   取消，**那么**系统拒绝并说明该任务已结束。
4. **假定**用户 B 请求取消用户 A 的任务，**那么**系统拒绝且不影响
   该任务（同样不承认其存在）。
5. **假定**任务已被取消，**当**用户查看任务与产物，**那么**状态明确
   为已取消，且不会留下可被误认为成功成品的结果记录。

### 用户故事 5 - 无密钥、断网环境下的完整离线演示（优先级：P2）

作为运维者/验收者，我打开一个"假模式"开关：不需要任何已配置的外部
密钥、机器也不访问任何外部服务，就能把"提交任务→后台执行→阶段推进
→成功完成并可在历史中查看"的完整流程演示一遍。这保证每个验收环境
（包括 CI 与断网机器）都能零成本验证流水线，且假模式绝不向真实外部
服务发出请求。

**为什么是这个优先级**：真实转写一次耗时数分钟且产生外部费用，离线
可验收是项目宪法要求；它不产生独立的终端用户业务价值，故列 P2，
但它是本特性能否被验收的硬门槛。

**独立测试**：在不配置任何密钥、禁用外网的条件下开启假模式，提交
任务，确认任务一路推进到"已完成"并出现结果摘要；全过程无外部请求。

**验收场景**：

1. **假定**系统以假模式运行且未配置任何密钥，**当**用户提交一个任务，
   **那么**任务正常创建并执行，不因缺少密钥被拒绝。
2. **假定**假模式任务正在执行，**当**观察其全过程，**那么**六个阶段
   与进度、状态更新与真实模式结构完全一致，最终产出结构完整的样例
   成品（章节齐全、可被后续阅读特性消费）。
3. **假定**系统处于假模式，**当**执行任务，**那么**不向论文解析服务、
   大模型服务或 arXiv 发起任何真实网络调用（测试可据此断言）。
4. **假定**系统处于正常模式，**当**提交任务，**那么**假模式绝不会被
   意外触发——该开关只由运维侧显式配置，用户无法通过请求参数自行
   开启。

---

### 边界情况

- 同一用户在两个浏览器标签页几乎同时提交：恰有一个进入运行，另一个
  收到"已有运行中任务"的明确拒绝。
- 同一用户几乎同时点击取消、而任务正好完成：结果唯一且无矛盾
  （见用户故事 4 场景 2）。
- 上传文件超过大小上限、或请求在传输途中中断：任务不得创建为残留
  记录，用户收到明确提示。
- 粘贴的链接不是受支持的论文链接、或 PDF 魔术字节校验失败：在进入
  转写前即作为"输入问题"失败，不消耗外部解析额度。
- 外部服务返回鉴权失败（密钥错误/失效）：归类为"服务问题"并提示
  检查密钥，与"链接不合法"这类输入问题明确区分。
- 外部服务超时或临时 5xx：归类为"服务问题"，提示可稍后重试；系统
  不在本特性内实现自动重试。
- 服务重启打断运行中的任务：重启后标记为中断（系统类），允许用户
  基于同一来源重新提交，不自动续跑。
- 用户连续提交同一篇论文：允许创建多个独立任务（每次任务标识与
  产物目录独立），但仍受"每用户一个运行中任务"约束。
- 假模式所需的样例物料缺失：系统给出明确的运维侧错误信息（系统类），
  而不是静默产出空成品。
- 所有访问任务与产物的请求都必须经过身份认证与归属校验；系统不提供
  任何凭文件系统路径直接读取产物的入口。

## 需求 *（必填）*

### 功能需求

**密钥管理**

- **FR-001**：已登录用户必须能分别保存两个外部服务（论文解析、大模型
  转写）的密钥；每个用户对每个服务至多保存一份当前密钥，可覆盖更新、
  可删除。
- **FR-002**：密钥必须以加密形式持久化，加密主密钥只能来自服务端
  环境配置；严禁明文落库、严禁写入日志，严禁随任何接口响应返回完整
  密钥；接口仅返回掩码与"是否已配置"。
- **FR-003**：密钥的读取、更新、删除必须限定为其属主；服务端在执行
  任务时于服务边界内部解密使用，解密后的明文不得出现在响应、状态
  文案或日志中。

**任务提交与执行**

- **FR-004**：用户必须能以两种来源提交任务：受支持的论文链接，或
  本地上传的 PDF（大小与格式受限）；两种来源在服务端统一校验，非法
  输入在转写开始前被拒绝。
- **FR-005**：提交请求必须立即返回任务记录，转写过程在后台执行，
  不得阻塞提交请求；执行能力必须定义在稳定接口之后，使未来从进程内
  执行替换为外部队列时无需改动对外接口。
- **FR-006**：每个用户同一时间至多允许一个排队或运行中的任务；系统
  必须存在可配置的全局运行任务上限。不同用户的任务相互隔离、不互相
  阻塞（在全局上限内）。
- **FR-007**：任务状态必须持久化且至少包含：排队、运行中、已完成、
  已失败、已取消；运行中必须记录当前阶段（六阶段之一）、0–1 进度与
  状态文字；已完成记录结果摘要（标题、章节数、总字数等）。
- **FR-008**：转写所需的全部文件（上传原件、中间产物、成品）必须存放
  在以"用户标识 + 任务标识"隔离的私有目录下；任何文件只能经需要登录
  且校验归属的服务端能力间接提供，严禁凭裸文件系统路径暴露。

**取消**

- **FR-009**：任务属主必须能取消排队或运行中的任务；取消只在阶段
  边界生效（解析轮询循环的等待间隙、相邻章节转写之间），生成过程中
  的硬中断不在范围内；取消后任务进入已取消终态且不产生成功成品。
- **FR-010**：核心转写逻辑仅允许以"新增一个默认关闭的可选取消信号
  参数"这一增量方式支持取消；除此之外核心代码与既有行为保持零改动，
  新参数必须带默认值，不改变任何现有调用。

**失败映射**

- **FR-011**：所有任务失败必须映射为彼此可区分的三类面向用户的结果：
  输入问题（用户修正后可重试）、服务问题（外部服务故障/超时/密钥被
  拒绝，稍后或更换密钥可重试）、系统问题（内部故障，联系维护者）；
  每类都附带可理解、可行动的中文说明，前端不得展示堆栈或内部细节。

**归属与隔离**

- **FR-012**：所有任务相关能力（查看、取消、以及未来的产物访问）必须
  通过统一的服务端归属校验，对照已认证用户标识执行；访问不存在或不
  属于自己的任务时一律以"不存在"处理，不得泄露任务归属与存在性。

**假模式（离线验收）**

- **FR-013**：系统必须支持由运维侧显式开关的假模式：开启后无需配置
  任何密钥、不向任何外部服务发起真实请求，即可走通提交→后台执行→
  阶段推进→完成并产出结构完整样例成品的全流程；该开关不得被普通
  用户请求影响或覆盖。

**工程与验收约束**

- **FR-014**：新增的服务端运行时依赖必须独立于核心流水线的既有依赖
  清单，核心白名单一行不改；密钥加密等新增能力只能加在 Web 层。
- **FR-015**：前端必须在 Spec 001 的统一布局与请求通道内新增：密钥
  设置页、任务提交页（链接/上传两种来源）、任务列表与任务状态详情
  （含进度快照、结果摘要、三类失败原因）、取消操作；不得新建独立
  布局或绕过统一认证/请求通道。
- **FR-016**：上述全部能力必须有自动化测试覆盖，且测试可在无外部
  网络、无真实密钥的条件下运行（以假模式执行真实的状态流转）；前端
  行为以手工验收为准。前端轮询刷新仅为本特性的临时手段，实时推送
  明确留待 Spec 003。

### 关键实体 *（涉及数据时必填）*

- **密钥凭据（Credential）**：某个用户为某个外部服务保存的密钥记录。
  关键属性：属主用户、服务种类（论文解析 / 大模型转写）、加密后的
  密文、用于展示的掩码、创建/更新时间。每用户每服务种类至多一份。
- **转写任务（Task）**：一次转写请求的完整记录。关键属性：任务标识、
  属主用户、来源种类（论文链接 / 本地上传）与来源引用、状态机当前
  状态、当前阶段与进度信息、失败分类与用户可懂信息、结果摘要、
  创建/开始/完成时间、私有产物目录的内部定位（不对外暴露路径）。
- **任务产物（Run Artifacts）**：任务私有目录下的上传原件、解析中间
  产物、图片与最终成品文件；按用户标识与任务标识双重隔离，本特性
  只负责安全落盘与归属管控，在线阅读与成品下载由后续特性提供。

## 成功标准 *（必填）*

### 可测量结果

- **SC-001**：新用户在配置好两个密钥后，2 分钟内能成功提交第一个任务
  并看到它进入后台执行；提交操作本身在 2 秒内返回，浏览器全程不被
  转写过程阻塞。
- **SC-002**：100% 的任务查询、取消与产物相关访问都经过属主校验；
  在跨用户越权访问测试（直接请求他人任务标识）中拦截率 100%。
- **SC-003**：100% 的失败任务都呈现三类可区分结果之一并附带可行动
  说明；验收中故意制造的链接非法、密钥无效、外部超时三类故障分别
  被正确归类，错分率为 0。
- **SC-004**：100% 的密钥在存储与任何接口响应中都不以明文出现；
  代码与日志审查中无法还原任何已保存密钥。
- **SC-005**：在无密钥、禁用外网的假模式环境下，"提交→执行→六阶段
  推进→完成→历史可见结果摘要"全流程成功率 100%，且外部服务请求
  计数为 0；自动化测试套件在断网条件下全部通过。
- **SC-006**：取消请求发出后，任务 100% 不进入任何尚未开始的新阶段，

  矛盾状态。
- **SC-007**：服务重启后，重启前处于运行中的任务 100% 被标记为中断
  （系统类、可重新提交），不存在永远卡在运行中的任务。

## 假设

- 外部服务沿用核心流水线当前支持的两家：论文解析服务与大模型转写
  服务；每用户自备密钥，不提供系统级共享密钥池。
- 转写的六个业务阶段、分章结构与既有核心流水线保持一致；本特性只
  做编排、持久化与呈现，不改动转写质量逻辑与提示词资产。
- 链接来源本阶段仅支持 arXiv；其他期刊链接与纯图片扫描件的高质量
  支持不在本特性（沿用核心现有的识别与报错能力）。
- 上传 PDF 大小上限取 50MB；超限在任务创建前拒绝。该数值为产品
  默认值，后续可调整。
- 本阶段执行方式为单台服务器上的进程内后台执行，不引入外部消息
  队列与分布式 worker；但对外接口与执行解耦，未来可替换。
- 系统不自动重试失败任务，也不做任务配额计费；用户可基于同一来源
  重新手动提交。
- 实时进度推送、完成后的在线阅读器（分章导航、公式与图片渲染、
  折叠区）与成品 Markdown 下载属于下一特性（Spec 003）；本特性只
  保证成品已按归属安全落盘、结果摘要可查。
- 假模式所需的样例物料由系统在测试/演示环境内置或自动准备，验收者
  无需自备真实论文解析产物；具体物料策略在技术方案中确定。
- 部署目标仍是本地开发机与可信内网环境；公网运维加固（传输加密、
  上传病毒扫描、对象存储等）不在范围内，但归属隔离与密钥加密的
  代码结构不得阻碍未来加固。
