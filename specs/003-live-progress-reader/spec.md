# 特性规格：实时进度与成品阅读

**特性分支**：`003-live-progress-reader`

**创建日期**：2026-09-28

**状态**：草稿

**输入**：用户描述："在 002 之上提供 SSE 实时进度、成品在线阅读器（分章/公式/图片/折叠区）与成品打包下载（Markdown + 图片 zip）；本特性前端只搭功能框架，视觉精修归下一特性。"

## 用户场景与测试 *（必填）*

### 用户故事 1 - 不刷新页面，实时看到任务推进（优先级：P1）

作为已登录用户，我提交转写任务后停在任务页上，不必手动刷新，
就能近实时看到任务从排队依次走过摄取、解析、归一化、规划、分章
转写、拼装六个阶段，直到成功、失败或取消。网络闪断后页面会自己
恢复；服务重启打断任务时，我重连看到的是明确的"因中断终止"而不
是永远转圈。我打开多个标签页、或别人猜测我的任务，都不会串扰。

**为什么是这个优先级**：实时进度是本特性存在的前提；002 的 3 秒
轮询是明确标注的临时手段，任务一旦真跑（真实模式数分钟），轮询
的延迟与无谓请求是最直观的体验短板，且阅读/下载入口都要靠"任务
何时完成"这一信号触发。

**独立测试**：假模式下提交任务后双手离开键盘，观察页面自动从
排队推进到已完成；手动掐断网络几秒再恢复，页面自动追上真实状态；
重启后端后重连，残留任务显示中断。

**验收场景**：

1. **假定**用户打开自己一个活动任务的详情页（或任务列表），
   **当**页面与服务端建立实时连接，**那么**首先收到当前状态快照，
   此后每次阶段或进度变化都在约 1 秒内自动反映，全程不刷新页面、
   不做定时轮询。
2. **假定**用户刚提交了一个任务，**当**后台依次推进六个阶段，
   **那么**用户在同一页面连续看到阶段名、进度比例与状态文字更新，
   最终自动停在成功（或失败、取消）的终态，终态后页面不再变化。
3. **假定**用户在任务已经结束后才打开页面，**当**连接建立，
   **那么**用户立即得到终态快照，不会停留在"排队/运行中"的假象。
4. **假定**推送连接中途断开（网络抖动），**当**连接恢复，**那么**
   页面先以服务端快照重新对齐再继续接收更新，不出现进度倒退、
   重复完成闪烁或与历史查询相矛盾的状态。
5. **假定**服务在任务运行期间重启（任务按 002 规则标记为中断），
   **当**页面重连，**那么**该任务明确显示为系统类失败"服务曾
   重启，该任务被中断，请重新提交"，而不是永远运行中。
6. **假定**用户未登录，或用户 B 尝试订阅用户 A 的任务，**那么**
   连接被拒绝；对 B 一律表现为"任务不存在"，不承认 A 的任务存在。
7. **假定**同一用户在多个浏览器标签页打开任务页，**当**任务
   推进，**那么**每个标签独立收到推送、各自正确显示，互不影响。
8. **假定**用户的浏览器环境无法维持推送连接，**当**页面检测到
   通道不可用，**那么**降级为手动刷新可用、并以低频快照兜底的
   方式继续提供真实状态，页面不白屏、不错报终态。

### 用户故事 2 - 在网页里舒适阅读转写成品（优先级：P1）

作为已登录用户，任务成功后我想直接在网页里读成品：左侧（或
顶部）有章节导航，七个章节一键跳转；数学公式（行内与行间）被
正确排版；图片随文显示；原文中被收进折叠区的细节可以展开/收起。
未完成、失败、已取消的任务不会向我展示半成品。我确信即使论文
内容里夹带了恶意脚本，也不会在我的浏览器里执行。

**为什么是这个优先级**：阅读器是整条流水线的价值兑现点——002
只把成品安全落盘，用户目前拿不到、看不到；它与实时进度共同构成
"提交→等待→阅读"的闭环。下载是其次的带走方式，故阅读列 P1、
下载列 P2。

**独立测试**：假模式任务成功后进入阅读器，核对七章导航、含公式
的章节、含图片的章节、折叠区四类元素；再用失败/取消任务与他人
任务验证入口与内容均不可达。

**验收场景**：

1. **假定**用户有一个已完成任务，**当**从任务列表或详情进入
   阅读器，**那么**页面呈现成品标题、章节导航与正文，风格位于
   应用统一登录布局之内。
2. **假定**任务未完成（排队/运行中）、已失败或已取消，**当**
   用户尝试打开其阅读器，**那么**系统拒绝并明确说明（运行中
   提示尚未完成），不返回任何半成品正文或图片。
3. **假定**成品包含七个章节，**当**阅读时，**那么**导航按成品
   顺序列出全部章节标题，点击可定位到对应章节，当前阅读位置
   可辨识；刷新或从外部深链进入可直达指定章节。
4. **假定**正文中包含行内与行间数学公式，**当**呈现该章节，
   **那么**公式被正确排版显示（而非原始定界符源码）。
5. **假定**正文中引用了随文图片，**当**呈现该章节，**那么**
   图片在对应位置正常显示；个别图片缺失时显示占位，不破坏整页
   排版。
6. **假定**正文中存在折叠区，**当**阅读时，**那么**折叠区默认
   收起、标题可见，可展开查看细节并再次收起。
7. **假定**成品文本中夹带脚本、事件属性或试图引用外站资源的
   内容，**当**页面渲染成品，**那么**这些内容不被执行、不发起
   非受控外部请求，页面只呈现安全排版；图片只能来自系统受控的
   本任务资源。
8. **假定**用户 B 直接使用用户 A 的阅读链接、章节内容或图片
   地址，**那么**一律得到"任务不存在"，任何正文字节与图片字节
   都不返回；未登录同样被拒绝。
9. **假定**深链指向的章节标识不存在，**当**打开该链接，**那么**
   页面回落到文档开头并保持可读，不报错、不白屏。

### 用户故事 3 - 把成品打包下载到本地（优先级：P2）

作为已登录用户，我想把成品保存到本地，在自己习惯的工具里
继续使用：下载得到一个压缩包，里面是成品 Markdown 和它引用
的图片，保持原有相对目录结构，解压后用任意常见 Markdown
工具打开都能看到图文完整的成品。压缩包与内部文件名能辨认出
是哪篇论文；同样只有属主能下载，服务器路径不会出现在任何
提示里。

**为什么是这个优先级**：下载是"带走成品"的自然诉求，但在线
阅读已经兑现核心价值；下载依附于同一套归属校验与受控资源
能力。

**独立测试**：假模式成功任务点下载，得到 zip；解压后
Markdown 与在线正文逐字一致、images 目录图片齐全且本地打开
图片正常显示；换用户、未登录、非成功任务均被拒绝。

**验收场景**：

1. **假定**用户有一个已完成任务，**当**触发下载，**那么**浏览器
   保存一个压缩包（.zip），其中包含与在线阅读器正文同源、
   逐字一致的成品 Markdown，以及该成品引用的图片（位于
   images/ 目录、保持相对路径结构）；解压后用常见 Markdown
   工具打开，图文完整可看。
2. **假定**论文标题包含特殊字符，**当**生成压缩包名与包内
   Markdown 文件名，**那么**名称仍可辨认且不包含路径分隔符、
   控制字符等可能影响安全解压与保存的内容。
3. **假定**成品没有任何图片（纯文本成品），**当**下载，**那么**
   仍正常得到只含 Markdown 的压缩包，不报错。
4. **假定**任务未成功，**当**用户尝试下载，**那么**没有下载
   入口；直接构造下载请求也被拒绝，不返回半成品。
5. **假定**用户 B 或未登录者请求 A 的成品下载，**那么**一律
   "任务不存在"/拒绝，不暴露成品是否存在与服务器存储位置。

### 用户故事 4 - 断网假模式下验收新能力（优先级：P2）

作为运维者/验收者，我在不配置任何密钥、机器不访问外部服务的
假模式下，把"提交→实时推进→在线阅读（公式/图片/折叠）→
打包下载"整条新链路完整演一遍；历史上 002 产出的成功任务也能
直接在新阅读器打开。

**为什么是这个优先级**：宪法原则七要求每个特性默认离线可验收；
它本身不产生终端用户新业务价值，故列 P2，但是否可验收的硬门槛。

**独立测试**：断网 + 无密钥 + 假模式，完成上述全流程，并以
哨兵断言零外部请求。

**验收场景**：

1. **假定**系统以假模式运行且无任何密钥，**当**用户提交任务并
   停在任务页，**那么**经实时推送看到六阶段连续推进到成功，
   全程无外部请求。
2. **假定**假模式任务成功，**当**进入阅读器并下载，**那么**
   七章导航、公式、图片、折叠区全部正确呈现，下载得到内容一致
   的成品压缩包（Markdown + images/）；阅读页保留"演示任务"
   辨识。
3. **假定**系统中存在 002 时期已成功的历史任务（成品已落盘），
   **当**升级后打开它，**那么**阅读器与下载同样可用，无需重新
   跑任务。
4. **假定**系统处于正常模式，**当**使用新能力，**那么**假模式
   开关仍只由运维侧控制，任何请求参数都不能影响它。

### 边界情况

- 连接建立的瞬间任务正好进入终态：首条快照即终态，之后安静，
  不出现短暂运行中又跳变的矛盾观感。
- 推送消息重复或乱序到达（断线重传、多标签）：界面以服务端
  快照与阶段/进度单调推进为准，绝不倒退、不重复计数。
- 任务在取消请求与完成竞争中结束（沿用 002）：推送送达的终态
  与历史查询完全一致，阅读入口只在成功时出现。
- 服务重启期间页面持续打开：连接断开→自动重连→收到中断标记，
  不需要用户手动刷新。
- 浏览器不支持或被禁用实时推送：降级为低频快照获取 + 手动
  刷新，阅读、下载、历史全部照常可用。
- 成品中的图片链接是死链（002 已统计死链）：阅读器显示占位，
  其余内容与下载不受影响。
- 论文标题为空或全部是特殊字符：压缩包名与包内 Markdown 文件名
  回落到安全的默认名（如任务标识），仍可正常保存与解压。
- 成品无图片：压缩包只含 Markdown 也能正常下载；成品引用了
  images/ 中实际不存在的死链图片：打包只收录真实存在的图片
  文件，不伪造占位文件。
- 成品正文很长、图片较多（单篇论文量级）：一次打开与章节跳转
  不发生可感知的卡顿；不做分页加载。
- 深链章节标识非法或不存在：回落到文档开头，不暴露错误堆栈。
- 成品含大量折叠区与公式混合排版：展开/收起不影响公式排版与
  滚动定位。
- 所有成品访问（正文、图片、下载）都必须经过身份认证与归属
  校验；系统不提供任何凭文件系统路径直接读取的入口。

## 需求 *（必填）*

### 功能需求

**实时进度**

- **FR-001**：系统必须为已登录用户提供任务状态的实时推送
  能力：连接建立时首先送达当前状态快照，此后任务在排队、六个
  阶段之间每次状态/进度/状态文字变化时持续推送，直至终态；
  用户无需手动刷新或等待定时轮询即可近实时（约 1 秒内）看到
  变化。
- **FR-002**：对实时推送的订阅必须经过身份认证与统一归属校验：
  未认证拒绝；订阅不存在或不属于自己的任务一律按"不存在"处理，
  不泄露任务存在性；推送内容口径与 002 的任务快照一致，不得
  包含文件路径、密文或任何他人数据。
- **FR-003**：终态必须可靠送达且不依赖订阅时机：任务结束后才
  建立的连接也要立即得到终态快照；连接中断后客户端必须能自动
  重连、先以服务端快照对齐再继续；重复或迟到的消息不得造成
  界面状态倒退或与历史查询矛盾。
- **FR-004**：实时通道不可用（环境限制或持续连接失败）时，
  必须降级为可手动刷新、并以低频快照兜底的方式获取真实状态；
  002 的持续定时轮询由实时通道取代，同一任务不得并存两套持续
  刷新行为。

**在线阅读器**

- **FR-005**：系统必须为已完成任务提供成品内容的只读获取能力，
  支撑网页阅读器呈现成品标题、按成品顺序排列的章节导航与各章
  正文；一次获取以单篇论文成品为规模前提，不做分页。
- **FR-006**：阅读器必须正确呈现四类成品要素：分章导航与定位
  （含刷新/深链直达指定章节、当前位置可辨识）、行内与行间
  数学公式、随文图片、可展开与收起的折叠区；缺失图片以占位
  处理而不破坏排版。
- **FR-007**：成品中的图片必须经需要登录且校验归属的受控资源
  能力提供：服务端依据已认证用户、任务标识与资源标识定位文件，
  不接受文件系统路径参数，禁止目录逃逸，越界或非本任务资源
  一律拒绝。
- **FR-008**：成品正文属于来自外部文档的不可信内容，渲染时
  必须消毒：脚本、事件属性、脚本化链接等不得执行，图片等外部
  资源只能指向系统受控来源，不得因渲染成品而发起任意外站请求。
- **FR-009**：只有已完成任务可以打开阅读器与获取正文/图片；
  排队、运行中、失败、已取消任务必须被明确拒绝并给出可懂说明
  （运行中提示尚未完成），不泄露半成品字节；他人与不存在任务
  一律"不存在"。
- **FR-010**：阅读页面必须位于 001/002 既有的统一布局、登录
  守卫与导航之内；支持章节深链；非法章节标识回落到文档开头，
  不报错、不白屏。

**成品下载**

- **FR-011**：系统必须提供已完成任务成品的归属校验打包下载：
  一个压缩包，内含与在线成品逐字一致的成品 Markdown 及其引用
  的图片（保持 images/ 相对目录结构，仅收录该任务目录下真实
  存在的图片），用户解压后在常见 Markdown 工具中图文完整
  可看；压缩包名与包内文件名均由成品标题派生并做同等安全化
  处理（无路径分隔符、控制字符与 Zip Slip 风险，无法据此推断
  服务器存储位置），标题不可用时回落到安全默认名；非成功任务、
  他人任务、未认证请求一律拒绝。

**横切约束**

- **FR-012**：实时推送、阅读器、下载等全部新页面与新连接必须
  复用既有唯一身份令牌与统一请求/连接口径，不得新建第二套
  登录态、布局或数据访问通道；前端仍不得直接访问文件系统或
  自行拼装资源定位。
- **FR-013**：本特性不得改动核心转写逻辑、提示词资产与既有
  成品结构：实时推送由 Web 层基于 002 已接入的阶段进度回调
  向外广播，阅读器只消费已落盘成品；核心依赖白名单一行不改，
  002 的取消信号特许增量不扩大。
- **FR-014**：实时推送、在线阅读、成品下载必须全部能在无密钥、
  零外部调用的假模式下端到端演示并纳入自动化/手工验收；开关
  仍只能由运维侧配置；002 时期产出的成功任务在升级后可直接
  阅读与下载。
- **FR-015**：上述全部能力必须有自动化测试覆盖，测试在无外部
  网络、无真实密钥条件下运行（推送以假模式任务的真实阶段流
  驱动，归属/消毒/文件名校验以断言固化）；前端渲染与公式、
  折叠区观感以手工验收为准。
- **FR-016**：本特性的前端以**功能框架完整**为交付标准：全部
  新页面位于既有统一布局内，核心功能入口（提交后的实时状态、
  阅读、下载、取消）可达、信息正确、交互闭环；不做视觉精修
  （配色与排版体系、间距/字号的像素级打磨、动效、响应式与
  移动端适配、空态/异常态的视觉设计、暗色模式等），该部分
  明确归下一特性，本特性不为视觉效果返工后端。

### 关键实体 *（涉及数据时必填）*

- **进度推送事件**：任务一次状态变化的瞬时推送消息。关键属性：
  任务标识、状态（排队/运行中/已完成/已失败/已取消）、当前
  阶段、0–1 进度、状态文字、是否终态。它是瞬时消息、不持久化；
  连接建立后的首条事件为任务当前快照，断线恢复与晚订阅一律以
  快照对齐，不回放历史事件。
- **成品章节**：成功任务成品中可供导航与分章呈现的逻辑单元。
  关键属性：章节标识（slug）、章节标题、章节正文（Markdown）；
  章节集合与顺序沿用 002 已落盘成品（固定七章结构）。
- **成品资源**：任务私有目录下的成品 Markdown 与其引用的图片
  文件。仅属主经登录与归属校验后可只读访问（正文、受控图片、
  打包下载）；资源定位由服务端按用户标识+任务标识+资源标识
  拼出，不接受任何外部传入路径。下载形态为把成品 Markdown 与
  images/ 下真实存在的图片按原相对结构打成的压缩包。

## 假设

- 实时通道采用宪法既定的"服务器→浏览器单向推送"形态，单机
  进程内广播，不引入消息队列、外部推送服务或双向长连接；与
  002 的进程内执行模型一致，未来替换执行器时推送订阅口径不变。
- 进度事件不持久化为时间线表：任务表仍只保存最新状态快照
  （沿用 002），断线恢复与历史不做事件回放。
- Markdown 到安全页面的渲染在浏览器侧完成，服务端只返回成品
  原文与受控图片字节；公式定界符、折叠区与图片链接的成品格式
  沿用核心现有产物，本特性不为渲染去改变核心输出。
- 下载形态为单个 zip 压缩包（成品 Markdown + images/ 目录，
  保持相对结构）；不导出 PDF/EPUB、不提供上传原件（PDF）
  下载，也不提供逐张图片的单独下载入口。
- 本特性前端只交付功能框架：布局沿用 001 既有框架，组件使用
  既有 Naive UI 默认形态把功能与信息组织正确即可；界面视觉
  精修（设计语言、配色与字体排版体系、间距规范、动效、响应式
  /移动端、空态与异常态插画、暗色模式等）统一归下一特性
  （Spec 004，暂名"界面打磨"），不在本特性验收范围内。
- 任务删除、重命名、重试的按钮级操作不在本特性内；重新提交
  仍等于新建任务（002 已支持）。
- 阅读器只面向已完成任务；失败原因展示仍沿用 002 的三分类
  页面，不在阅读器内重复实现。
- 成品规模以单篇论文为前提（数万字、数十张图量级），正文
  一次性获取可接受，不做分页、虚拟列表或服务端章节切片。
- 假模式样例物料沿用 002 的 `web/fixtures/fake_run`（含公式与
  表格章节）；如阅读器验收需要更丰富的折叠区/图片样例，仅在
  Web 层物料目录内扩充，不改核心。
- 部署目标仍是本地开发机与可信内网；推送连接的公网加固
  （鉴权代理、限流等）不在本特性，但所有新连接的认证与归属
  结构不得阻碍未来加固。
