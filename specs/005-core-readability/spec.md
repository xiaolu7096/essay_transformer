# 特性规格：Core 转写可读性优化（章节归类修复 + 空章中性降级 + 折叠区修复）

**特性分支**：`005-core-readability`

**创建日期**：2026-10-07

**状态**：待评审（已按"保留固定 7 章"方向修订）

**输入**：用户以 test 账号转写 survey 论文 *"A Survey on Question Answering over Visually Rich Documents"*（任务 `2d26f6b9`）后，从读者视角提出：转写稿存在章节错位、空章、缺失提示刷屏、表格截断、图片丢失、参考文献粗糙等问题，需要优化 Core 层。

**调查证据**（同一任务目录 `runs/922d7511-.../2d26f6b9-.../`）：

- `output.md`（541 行）：第 3 章、第 6 章整章为"输入为空"的工程化说明并泄漏 `blk-xxxx` 内部编号；第 5 章实际装入原文 §2.1 方法内容；原文 §7 Limitations 混入第 4 章；10+ 处"解析缺失"占位；3 张折叠表在 HTML 标签中途截断；5 张图仅引用 1 张；110+ 条参考文献无编号、部分 OCR 残缺。
- `parsed/..._content_list.json`（215 条）：原文结构完整（23 个标题小节都在），但含 13 个空 text 条目（`content_list[9/21/26/92]` 等，位置与丢失的架构图重合）；仅 1 个 image 条目；3 张大表 `table_body` 长度 3078/4376/3082 字符且 HTML 本身完整。
- 结论：**空章致歉信与章节错位是 planner/pipeline 的问题，不是 MinerU 灾难**；表格截断是 assemble 的 `[:3000]` 硬切 bug；缺失占位与丢图根因在 MinerU，但呈现方式由 Core 决定。

**已确认的设计决策**：

- **保留固定 7 章模板，不做动态章节**：成品永远是 tldr / intro / conclusion / related / method / experiments / wrapup 七章，章标题与编号（0~6）保持现状，读者心智和前端结构都不变。
- **空章不调 LLM，改为按章类型预写的中性固定文案**：某章在 planner 判定为"无实质内容"时，不请求 DeepSeek，直接填入一句面向读者的中性说明（例如 related 空章："本文未设独立的相关工作章节，相关背景与前人方法已随正文介绍。"）。固定文案按 slug 预置在 Core 代码中，是成稿的一部分（正常正文样式，非警告框），**绝不出现**"输入为空/请重新解析/未编造补全"这类工程语言，也不出现任何内部标识。
- **章节归类以"标题结构 + 层级归组"修复错位**：未分类顶级小节整体作为一组，子节强制跟随父节，消灭"§2 方法、§2.1 实验"的割裂；limitation/discussion 归结论/总评；不允许为了凑满 experiments 把方法组误判为实验章——experiments 空了就走中性降级。
- **parse_gap 呈现降级**：缺失块不再逐块把"原文解析缺失，未编造内容补全"插进正文；改为连续 gap 合并、位置感知的一次性弱提示，内部块 id（`blk-xxxx`）绝不进入 prompt 与读者可见文本。
- **折叠区不截断**：表格输出完整 HTML，不再按字符数硬切；表格用原文表题做可读标题，不用块 id。
- **参考文献保留编号与可点链接**：保留原文编号（无则顺序编号），能识别的 arXiv/DOI/URL 转链接；OCR 明显损坏条目做不改变语义的最小清理，不编造。
- **来源标注降噪 + 去斜体**：从"每段强制标注"放宽为"每小节至多一次集中标注"；来源标注不再使用斜体（现 `*（原文 §X，第 n 页）*` 整段斜体导致数字倾斜、观感奇怪），由 Core 统一转为 `<span class="src-note">…</span>` 非斜体轻样式；公式 LaTeX 不做加空格改写。
- **范围红线**：本特性只改 `core/`、`web/tests/` 下的 Core 测试，以及 `webui/src/styles/reader.css` 一处纯新增样式（`.src-note`，约 6 行），不改 `web/app`、`webui/` 其他代码。已核查 `webui/src/views/ReaderView.vue` 按 `sections` 数组遍历渲染，固定 7 章结构保持不变；`span` + `class` 已在 DOMPurify 白名单内，消毒链路不改。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 章标题与章内容相符，空章得体（优先级：P1）

作为读者，我打开一篇 survey（或任何没有独立"相关工作/实验"章的论文）的转写稿，七个章节都在、顺序不变；有内容的章装着与标题相符的内容，没有内容的章用一句自然的话告诉我"这篇论文没有这部分"，而不是给我看一封系统致歉信或把方法内容错放进实验章。

**为什么是这个优先级**：章节张冠李戴和整章工程化说明是"内容错误/穿帮"，直接摧毁读者信任，是本次调查中伤害最大的问题。

**独立测试**：用任务 `2d26f6b9` 的已有 parsed 产物在 fake LLM 模式下重跑全链路（再做一次真实重跑人工验收），逐章核对：7 章齐全；有内容章的标题与主题一致（§2.1 与父节 §2 同章；§7 Limitations 在结论/总评类章）；无内容章（related）展示的是固定中性文案，无工程语言、无内部 id，且该章没有触发 LLM 调用。

**验收场景**：

1. **假定**一篇论文没有任何被归类为 related_work 的小节，**当**转写完成时，**那么**成品仍包含「## 3 · 背景与相关工作」章，正文为该 slug 预置的一句中性说明（告知本文无独立相关工作、相关内容随正文介绍），不出现空标题、不出现"输入为空/请重新解析"文本。
2. **假定**原文 §2 为方法、§2.1 为其子节，**当**规划章节时，**那么** §2.1 与最近的顶级父节 §2 归入同一目标章，不得因"顺序分配"把 §2.1 单独判为 experiments。
3. **假定**原文有 Limitations 小节，**当**规划时，**那么**它进入 conclusion 或 wrapup 章，不进入方法教程章。
4. **假定**某章没有任何实质来源块（无段落/公式/图，仅有标题或全为缺失块），**当**执行 rewrite 时，**那么**该章不调用 LLM，成品中该章正文等于其预置固定文案。
5. **假定**论文为标准实验型论文（六类小节齐全），**当**转写时，**那么**七章全部由真实内容填充，固定降级文案只在确实无内容时出现，不得误吞正常章节内容。
6. **假定**读者通读任意一章（含降级章），**当**全文检查时，**那么**不出现 `blk-`、`content_list`、`fold`、`slug` 等工程概念词。

### 用户故事 2 - 解析缺失不再高频打断阅读（优先级：P1）

作为读者，我希望"原文此处没解析出来"这类提示偶尔出现一次可以接受，但不要每隔两三段就刷一条、更不要看到 `blk-0092` 这种内部编号；连续多个缺失合并成一条克制的提示。

**为什么是这个优先级**：本次稿件 10+ 处占位、几乎每屏一条，是仅次于章节错位的第二大体验硬伤；根因（MinerU 空块）Core 无法消除，但呈现完全由 Core 掌控。

**独立测试**：对含 13 个空 text 条目的同一 parsed 产物重跑，统计成品中读者可见的缺失提示次数与措辞；确认 prompt 与正文均无 `blk-[0-9]+`、`content_list[` 等内部标识。

**验收场景**：

1. **假定**同一小节/同一页内连续出现多个 parse_gap 块，**当**构造章节输入时，**那么**它们合并为至多一条缺失提示（带页码范围），不逐条罗列。
2. **假定**缺失来自整图区域丢失（空 text 块位于疑似图片位置），**当**提示时，**那么**措辞指向"此处原文可能包含一张图，解析未提取"，区别于普通段落缺失，同样不含内部 id。
3. **假定**读者阅读任意一章正文，**当**全文检查时，**那么**不出现 `blk-` 前缀编号、`content_list`、`fold`、`slug` 等工程词（空章固定文案中也不允许）。
4. **假定**某章实质内容全部缺失、整章只剩 gap，**当**降级时，**那么**优先走用户故事 1 的固定文案（空章文案不再追加 gap 提示，避免一页内两条提示）。

### 用户故事 3 - 折叠区表格完整、可读、不截断（优先级：P1）

作为读者，我在文末折叠区展开实验数据表时，希望看到完整的表格（HTML 闭合、行列齐全），表格有可理解的名称（来自原文表题），而不是被拦腰截断的半截标签和 `blk-0025` 这种名字。

**为什么是这个优先级**：表格在标签中途截断是明确的数据损坏 bug（根因是 assemble 的 `html[:3000]`），让折叠区完全不可用。

**独立测试**：对含 3078/4376/3082 字符大表的同一产物重跑，展开折叠区检查 3 张表：HTML 标签全部闭合、尾部数据行完整；每张表展示原文表题（caption）而非块 id。

**验收场景**：

1. **假定**一张表 `table_body` 长度为 4376 字符，**当**写入折叠区时，**那么**输出完整 HTML，结尾为正常闭合标签（`</table>`），不出现 `...</t`、`...</tt` 这类截断。
2. **假定**表格带有原文表题（table_caption），**当**渲染折叠区时，**那么**以表题作为可见标题；仅当表题缺失时才退回"表（第 M 页）"中性文案，任何情况下不向读者显示 `blk-xxxx`。
3. **假定**折叠表格内容很长，**当**在阅读器展开时，**那么**依靠折叠区/页面滚动查看，内容不被字符数上限切断。

### 用户故事 4 - 图片尽量保留、缺失有交代（优先级：P2）

作为读者，我希望正文引用的架构图都能看到；若某张图 MinerU 完全没解析出来，我至少能知道"此处原有一张图"，而不是图片悄无声息消失，也不希望架构图仅因所在章节被当成数据图折走。

**为什么是这个优先级**：本次 5 张图仅 1 张有 image 条目，其余退化为空文本块；Core 无法恢复像素，但应做到"引用到的图都拷全、疑似丢图有提示、架构图不被误折叠"。

**独立测试**：重跑后核对 `images/` 目录与 markdown 图片引用一致（`dead_links` 为空）；方法/架构类 figure 保持在正文；丢失图片位置有弱提示。

**验收场景**：

1. **假定**某 figure 块被正文或折叠区引用，**当**拷贝图片时，**那么**对应文件必须存在于任务 `images/` 目录，`check_image_links` 返回的死链列表为空。
2. **假定**一张 figure 仅因所属章节为 experiments 就被现规则折叠，**当**该图实际是架构/流程图时，**那么**新规则按图自身 caption 特征判定，架构图保留在正文，不一刀切。
3. **假定**MinerU 把图区域输出为空 text 块（无 image 条目），**当**归一化时，**那么**该位置标记为"疑似图片缺失"（带页码），按用户故事 2 的合并规则呈现，不静默吞掉、不伪造图片链接。

### 用户故事 5 - 参考文献可用、来源标注不刷屏（优先级：P2）

作为读者，我希望折叠区参考文献有编号、关键条目（arXiv/DOI）可点击、损坏条目不影响阅读；正文来源标注克制、非斜体（不要每段结尾挂一条倾斜的页码，数字斜着很奇怪）。

**为什么是这个优先级**：影响专业度与阅读流畅感，但不造成内容错误，故列 P2。

**独立测试**：检查参考文献折叠区：条目有序号、可识别链接可点；损坏条目无明显乱码尾缀；通读任意一章，来源标注每小节至多一处、均为非斜体轻样式（无 `*（原文` 斜体标记残留）。

**验收场景**：

1. **假定**参考文献原文带编号（`[12]`），**当**生成折叠区时，**那么**保留并展示编号；原文无编号时按出现顺序从 1 编号。
2. **假定**参考文献文本含 arXiv id / DOI / URL，**当**输出时，**那么**转为可点击 Markdown 链接；无法识别的保持纯文本，不编造链接。
3. **假定**某条参考文献存在明显 OCR 残缺（如 `Preprint i 5`），**当**处理时，**那么**做不改变语义的最小清理（仅高置信白名单规则）；无法可靠修复时保留原文，不虚构作者/标题。
4. **假定**一章内连续多段都来自同一原文小节，**当**写来源标注时，**那么**合并为每小节至多一次（或章首集中标注），不逐段重复；且标注渲染为非斜体的 `<span class="src-note">原文 §X，第 Y 页</span>` 轻样式，不再出现 `*（原文 …）*` 斜体包裹。
5. **假定**公式来自原文，**当**输出 LaTeX 时，**那么**与回填后的原文一致，不额外插入空格或改写符号。

### 边界情况

- **论文类型差异**：标准实验型论文、纯综述、短篇（无结论/无相关工作）、带大量附录的论文，7 章都必须齐全且得体——有内容讲内容，没内容走固定文案，不出现致歉信。
- **多章同时为空**：一篇论文可能 related 与 experiments 同时为空；每章独立使用各自的固定文案，互不影响。
- **固定文案的风格**：降级文案必须与教程正文口吻一致（一句话、中文、面向读者），不用"本章为空/错误/缺失/解析"等系统视角词汇；具体文案在实现时由代码常量给出并在测试中锁定。
- **appendix 归属**：附录不占主线教程内容；其表格/数据集说明可进折叠区；附录存在不代表 wrapup 有实质正文，wrapup 无其他内容时仍走固定文案。
- **fake 模式与离线回归**：所有新规则在不调用真实 API 前提下可验证（复用 parsed 产物 + fake LLM）；现有 Core 离线测试与 fixtures 同步更新，不得删测试求通过。
- **API 契约**：`PaperResult.sections` 结构（slug/heading/content）与长度（恒为 7）不变；plan.json 仅新增可选字段（如 `empty_slugs`/降级原因），不删除既有字段；六阶段进度语义不变。

## 需求 *（必填）*

### 功能需求

**章节归类修复（normalize/planner）**

- **FR-001**：planner 必须为每个 slug 计算"是否有实质内容"：实质内容 = 该 slug 来源块中存在 ≥1 个非 heading、非 parse_gap、非 fold 的正文块（paragraph/equation/figure）。判定结果以 `"empty": true/false` 写入 `target_order` 各项，并在 plan 顶层新增 `"empty_slugs": [...]`（仅新增字段，FR 兼容）。
- **FR-002**：未分类小节的归属必须以**层级归组**为基础：以最高层级（数字编号最靠左，如 `2` 对 `2.1`）的未分类小节为组锚点，其所有下级小节强制同组；整组一次性判定目标 slug（method 或 experiments），判定依据结合锚点标题关键词与组内是否含结果/评测/数据对比内容，删除现有"第一个→method、第二个→experiments"的全局顺序瓜分逻辑与 `_find_parent_slug`。
- **FR-003**：章节归类关键词必须修正：`limitation`、`future work`、`discussion` 归 conclusion；`background`、`related`、`survey`、`overview`（作为背景小节时）归 related；`appendix`/`supplementary` 不占主线。注意论文总标题（text_level≤1 的 title 块）即使含 survey 等词也不得参与小节归类。
- **FR-004**：当全文没有真实评测/结果内容时，不得为凑满 experiments 把方法组判为实验；experiments 留空并走 FR-005 降级。
- **FR-005**：标准论文在新规则下，七章中原本有真实内容的章不得丢内容或误降级；允许的变化仅是"真正为空的章改用固定文案"。

**空章固定文案降级（planner/pipeline）**

- **FR-006**：必须在 Core 中为每个 slug 预置一句**面向读者**的中性降级文案常量（如 related："本文未设独立的相关工作章节，相关背景与前人方法已随正文介绍。"；experiments："本文以综述/方法阐述为主，未包含独立的实验评测章节。"；其余 slug 各一句，具体措辞实现时确定并在测试锁定）。文案为正常正文，不加警告样式。
- **FR-007**：pipeline 逐章 rewrite 必须跳过 `empty=true` 的 slug：不调用 `chat()`、不产生 API 费用，`section_contents[slug]` 直接取 FR-006 的固定文案；rewrite 阶段进度分母改为 7（章数不变），空章快速划过。
- **FR-008**：成品必须恒为 7 章，章标题与编号（`## 0 ·` … `## 6 ·`）、slug 顺序完全不变；降级章与正常章在拼装结构上无差异（同样有标题、正文）。
- **FR-009**：防御性兜底：非空章若 LLM 返回内容 `strip()` 后为空，退回该 slug 固定文案并打印一条日志，不输出空白正文。
- **FR-010**：固定文案中严禁出现工程词汇（至少屏蔽 `blk`、`content_list`、`parse`、`slug`、`fold`、`重新解析`、`未编造`、`输入`），由测试正则锁定。

**parse_gap 呈现降级（normalize/planner/prompt_builder/prompts）**

- **FR-011**：连续或同小节内的多个 parse_gap 必须在喂给 LLM 前合并为单个"缺失区间"（携带页码范围），不再逐块传入；发给 LLM 的块头不得出现内部 id（`[blk-0021]` 改为无语义序列定位，如 `[块12]` + type/section/page）。
- **FR-012**：prompts（system.md / section.md）必须明确：缺失提示每章至多一处、措辞中性简短（给定死例句式）、禁止内部标识、禁止命令读者；"不得编造缺失内容"的铁律保留。整章全缺时按 FR-007 走固定文案，prompt 中不再出现该章的 gap 罗列。
- **FR-013**：由"空 text 且 bbox 尺寸接近整栏/整图区域"识别出的疑似丢图位置，gap 必须带 `suspected: "figure"` 与页码，与普通文本缺失区分措辞；该判定保守，拿不准按普通 gap。

**折叠区与表格（assemble）**
